# AI 마음이 첫 버전 인수인계

작업 브랜치 `codex/maeumi-first-version`. 운영 대상은 `ai-heart/ai_heart`와 https://www.ai-heart.co.kr/이다.

## 확인한 상태

- Node.js 24에서 프로덕션 빌드와 TypeScript 검사를 통과했다. 구현 브랜치에 교원 인증, 학급 설정·입장, PDF, AI 응대, 받은함·알림, 삭제 코드가 있다.
- `npm run test:db`로 가상 데이터와 격리된 PostgreSQL에서 전체 마이그레이션, 학급 소유권, 코드 회전, 중복 문의, 경고 후 종료, 학급 종료 및 DB 연쇄 삭제를 검증했다.
- Windows 개발 환경에서 Supabase CLI를 초기화했다. Docker와 Podman이 없어 로컬 스택이 시작되지 않았다. Supabase Auth·Storage를 포함한 역할별 검수는 대기 중이다.
- 운영 DB는 변경하지 않았다. 운영 Vercel 프로젝트 조회는 팀 권한 확인이 필요하다. [초안 PR #1](https://github.com/smchae1008-lgtm/ai_heart/pull/1)을 열었으며 최초 커밋의 Vercel 체크는 성공했다. 전체 흐름 검수, main 병합, 병합 커밋의 운영 Ready 확인은 대기 중이다.

## 가상 데이터 검수 절차

1. 개발용 Supabase를 시작하고 마이그레이션을 적용한다. 개발용 URL과 Publishable key, 서버 전용 Secret key를 로컬 환경에 설정한다. Mailpit으로 OTP를 받는다. 운영팀 테스트 계정에 관리자 절차로 `app_metadata.maeumi_role=operator`를 지정한다.
2. 가상 교사로 로그인한다. 승인 대기 상태에서 학급 개설이 차단되는지 확인한다. 예시 PDF를 제출하고 운영팀 계정으로 반려한다. 교사에게 반려 사유가 표시되고 파일이 삭제되는지 확인한다. 재신청을 승인하고 파일 삭제를 확인한다.
3. 교사가 학급과 상담 시간을 저장한다. 문의처가 없으면 공개할 수 없는지 확인한 뒤 문의처를 추가하고 코드를 발급한다. 첫인사와 말투를 저장하고 예시 학사일정 PDF를 등록한다.
4. 가상 학부모로 로그인한다. 틀린 코드를 거절하고 올바른 코드로 입장하는지 확인한다. 같은 계정으로 재입장해도 입장 인원은 1명이어야 한다. 코드 재발급 후 이전 권한과 코드를 거절하는지 확인한다.
5. PDF에 있는 일정과 준비물, PDF에 없는 내용, 안전 확인이 시급한 문의, 개인 연락처 요청 두 건을 보낸다. 각각 출처, 일반민원 접수, 긴급도 상 알림, 재작성 안내와 두 번째 경고 시 종료를 확인한다.
6. 교사 받은함에서 요약, 긴급도, 예정된 알림 표시 시각, 원문을 확인한다. 다른 교사 계정으로 같은 원문 주소에 접근할 수 없어야 한다. 학급 종료 후 접수 차단과 기존 기록 열람을 확인한다. 학급을 삭제하고 DB 기록과 저장소 파일이 사라졌는지 확인한다. 두 로그인 계정은 유지되어야 한다.

검수 결과와 남은 결함을 PR에 기록한다. 팀과 운영 DB 적용 범위를 확인한 뒤 호환되는 마이그레이션을 먼저 적용한다. 병합 후 Vercel에서 배포 커밋과 Ready 상태를 확인하고 운영 주소를 검증한다.
