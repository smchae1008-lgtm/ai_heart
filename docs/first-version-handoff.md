# AI 마음이 첫 버전 인수인계

작업 브랜치 `codex/maeumi-first-version`. 운영 대상은 `ai-heart/ai_heart`와 https://www.ai-heart.co.kr/이다.

## 확인한 상태

- [GitHub Actions 브라우저 검수](https://github.com/smchae1008-lgtm/ai_heart/actions/runs/43612968039)에서 격리된 Supabase를 시작하고 가상 계정 3개의 OTP 로그인, 증명서 반려·재신청·승인·삭제, 학급 개설, 코드 입장과 인원 수, PDF 업로드, 교사의 문의 원문 열람, 학부모의 원문 접근 차단, 학급 삭제에 따른 Storage와 DB 정리를 검증했다. PDF 근거 답변은 가상 모델 응답으로 검증했다.
- `npm run test:db`로 마이그레이션, RLS, 학급 코드 재발급, 문의 중복 방지, 경고 후 대화 종료와 상담 시간에 따른 알림을 확인했다. 같은 CI에서 Auth API 연결과 Next.js 빌드도 통과했다.
- 별도 OpenAI 개발 호출에서 `gpt-6-luna`로 일정 원문 인용, 근거 부족 시 일반민원, 안전 문의 긴급도 상, 개인번호 요구의 악성민원, 악성민원과 긴급도 상의 동시 분류를 확인했다. 기존 기본 모델 `gpt-5.6-luna`는 사용한 개발 키에서 잔액 부족 오류를 반환했다.
- 첫 버전은 main에 반영했다. 운영 Supabase에서 마이그레이션 5개와 신규 테이블 5개의 RLS 활성화를 확인했다. 운영 OTP 수신과 내 계정 화면 접근을 확인했으며, Vercel Production에 Supabase 및 OpenAI 서버 키가 등록됐다. 두 키가 반영된 운영 배포의 PDF 업로드, 실제 AI 출처 답변, 문의 접수 결과는 아래 운영 검수에 기록했다.

## 운영 배포 범위

운영 Supabase `rikwramzpveuofxdlzha`에 `supabase/migrations/`의 SQL 5개를 순서대로 적용한다. 교원 인증, 학급·입장, 자료, 민원 테이블과 접근 정책, RPC, 비공개 Storage 버킷 2개를 생성한다. 기존 운영 데이터를 수정하거나 삭제하는 SQL은 포함되어 있지 않다.

운영 Supabase의 이메일 OTP 템플릿과 발송 설정을 확인한다. Vercel `ai-heart/ai_heart` Production에 Supabase URL·Publishable key·서버 전용 Secret key, OpenAI 키와 호출 가능한 모델을 설정한다. 마이그레이션 적용 후 main에 병합하고, Vercel 배포가 Ready인 커밋과 운영 로그인 및 앱의 DB 연결을 확인한다.

## 가상 데이터 검수 절차

1. 개발용 Supabase를 시작하고 마이그레이션을 적용한다. 개발용 URL과 Publishable key, 서버 전용 Secret key를 로컬 환경에 설정한다. Mailpit으로 OTP를 받는다. 운영팀 테스트 계정에 관리자 절차로 `app_metadata.maeumi_role=operator`를 지정한다.
2. 가상 교사로 로그인한다. 승인 대기 상태에서 학급 개설이 차단되는지 확인한다. 예시 PDF를 제출하고 운영팀 계정으로 반려한다. 교사에게 반려 사유가 표시되고 파일이 삭제되는지 확인한다. 재신청을 승인하고 파일 삭제를 확인한다.
3. 교사가 학급과 상담 시간을 저장한다. 문의처가 없으면 공개할 수 없는지 확인한 뒤 문의처를 추가하고 코드를 발급한다. 첫인사와 말투를 저장하고 예시 학사일정 PDF를 등록한다.
4. 가상 학부모로 로그인한다. 틀린 코드를 거절하고 올바른 코드로 입장하는지 확인한다. 같은 계정으로 재입장해도 입장 인원은 1명이어야 한다. 코드 재발급 후 이전 권한과 코드를 거절하는지 확인한다.
5. PDF에 있는 일정과 준비물, PDF에 없는 내용, 안전 확인이 시급한 문의, 개인 연락처 요청 두 건을 보낸다. 각각 출처, 일반민원 접수, 긴급도 상 알림, 재작성 안내와 두 번째 경고 시 종료를 확인한다.
6. 교사 받은함에서 요약, 긴급도, 예정된 알림 표시 시각, 원문을 확인한다. 다른 교사 계정으로 같은 원문 주소에 접근할 수 없어야 한다. 학급 종료 후 접수 차단과 기존 기록 열람을 확인한다. 학급을 삭제하고 DB 기록과 저장소 파일이 사라졌는지 확인한다. 두 로그인 계정은 유지되어야 한다.

검수 결과와 남은 결함을 PR에 기록한다. 팀과 운영 DB 적용 범위를 확인한 뒤 호환되는 마이그레이션을 먼저 적용한다. 병합 후 Vercel에서 배포 커밋과 Ready 상태를 확인하고 운영 주소를 검증한다.

## 운영 브라우저 검수 2026-11-15

- 승인된 가상 교사 계정으로 학급을 만들고 가상 문의처를 설정한 뒤 공개했다. 같은 계정으로 학급 코드 입장 화면을 통과했고 입장 인원은 1명으로 표시됐다. 별도 학부모 계정의 권한 검수는 격리된 CI에서 확인했다.
- 가상 학사일정 PDF 업로드가 운영에서 실패했다. 배포 파일에 PDF 추출 작업 파일을 포함한 main 커밋 0056c1b를 배포한 뒤 자료 목록에 PDF가 표시됐다.
- 가상 문의가 접수됐고 교사 받은함에 표시됐다. PDF에 있는 현장학습 일정을 물었을 때 OpenAI가 잔액 부족 오류를 반환해 교사 확인 경로로 넘어갔다. 운영 모델 설정을 gpt-6-luna로 변경했고 이 설정을 반영한 [운영 배포 2f04f43](https://vercel.com/ai-heart/ai_heart/DWPNwpAmgtaBPe3TGK5tUR3Jjyoo)가 Ready 상태가 된 뒤 재검수했다. 챗봇은 현장학습 날짜를 12월 18일로 답하고 PDF 파일명과 1쪽을 표시했다. 개별 상담 문의는 일반민원, 긴급도 중으로 접수됐으며 담당 교사 계정에서 요약과 원문을 열었다. 가상 학급과 자료는 운영 검수 재현용으로 남겼다.
